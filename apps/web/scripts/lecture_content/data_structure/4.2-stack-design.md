## 這個技術解決什麼問題

本節是「設計資料結構」型的堆疊題：除了 push／pop，還要 $O(1)$ 或 $O(\log n)$ 回答某個額外查詢——最小值（155）、最大值（716）、出現頻率最高的元素（895），或維護一組堆疊（1172）。

這類題目的共同槓桿是一個結構性事實：

> **後進先出讓「歷史狀態」天然被保存。** 彈出第 $k$ 個元素之後，系統回到的正是推入它之前的狀態；而那個狀態就躺在堆疊的下一格。

換句話說，**只要那個統計量可以逐格保存，就能 $O(1)$ 回退**。這是堆疊獨有的性質：佇列（先進先出）刪掉的是最舊的元素，剩下的元素從來沒有一起出現過某個「歷史狀態」，所以同樣的問題在佇列上就要用單調雙端佇列（5.4）或兩個堆疊來湊。**「為什麼堆疊做得到而佇列做不到」是本節最值得帶走的一句話。**

636（函式的獨佔時間）則是另一種形態：**堆疊直接模擬真實世界的呼叫堆疊**，因為日誌本身就是良巢狀的。

## 狀態／資料結構定義

**155 最小堆疊——寫法 A（輔助堆疊，推薦）**
- `std::vector<int> st`：主堆疊。
- `std::vector<int> mn`：同步堆疊，`mn[i]` = `st[0..i]` 的最小值。
- push：`st.push_back(x); mn.push_back(mn.empty() ? x : min(mn.back(), x));`
- pop：兩個一起 `pop_back()`。
- getMin：`mn.back()`。
- 空間 $O(n)$，但邏輯簡單、幾乎不會寫錯。**面試預設寫這個。**

**155 寫法 B（差值編碼，$O(1)$ 額外空間）**
- 只存一個 `long long` 的 `mn`，堆疊裡存的不是 $x$ 而是編碼值。
- push $x$：若 `st.empty()`，`mn = x`，推入 $x$；否則若 $x < mn$，推入 $2x - mn$（一個**小於 $x$** 的哨兵），再令 `mn = x`；否則直接推入 $x$。
- pop：若 `st.back() < mn`，說明它是哨兵，還原 `mn = 2*mn - st.back()`；再彈出。
- top：若 `st.back() < mn` 回傳 `mn`，否則回傳 `st.back()`。
- **必須用 `long long`**：$2x - mn$ 在 $x, mn$ 皆為 $\pm2^{31}$ 量級時會溢位 `int`。

**716 最大堆疊**：需要 `popMax()`（刪除任意位置的最大元素），輔助堆疊法失效（它只能回退，不能挖中間）。標準做法是**雙向鏈結串列 + 有序集合**：`std::list<int>` 保存序列，`std::map<int, vector<list::iterator>>` 按值索引位置。`popMax` 取 `map` 的最後一個鍵、取其最後一個迭代器、從 `list` 中 $O(1)$ 刪除。**所有操作 $O(\log n)$。**

**895 最大頻率堆疊**
- `unordered_map<int,int> cnt`：每個值目前的出現次數。
- `unordered_map<int, vector<int>> group`：`group[f]` = 「曾經達到過次數 $f$」的元素，按達到的時間順序排列。
- `int maxF`：目前最大次數。
- push $x$：`int c = ++cnt[x]; group[c].push_back(x); maxF = max(maxF, c);`
- pop：`int x = group[maxF].back(); group[maxF].pop_back(); --cnt[x]; if (group[maxF].empty()) --maxF; return x;`
- **注意這裡完全沒有「重新排序」或「堆」，全是 $O(1)$ 的陣列尾端操作。**

**636 函式的獨佔時間**：`vector<int> st`（正在執行的函式 id 鏈）+ `int prev`（上一個時間切點）+ `vector<int> ans`。

**1172 餐盤堆疊**：`vector<vector<int>> stacks` + `priority_queue<int, vector<int>, greater<>> avail`（未滿堆疊的下標，允許有過期項，懶刪除）。

## 不變量或正確性證明

**引理 1（155 輔助堆疊的正確性）。** 恆有 $\texttt{mn}[i] = \min\{\texttt{st}[0], \dots, \texttt{st}[i]\}$。

*證明（對操作次數歸納）。* push $x$ 時新增 $\texttt{mn}[i] = \min(\texttt{mn}[i-1], x) = \min(\min_{t<i}\texttt{st}[t],\ x) = \min_{t \le i}\texttt{st}[t]$；pop 只是移除最後一項，不影響前綴的定義。$\square$

**這條不變量成立的前提是「刪除的一定是最後推入的元素」。** 前綴最小值只能整格丟棄、不能從中間挖掉——這正是 716 的 `popMax` 讓輔助堆疊法失效的原因，也是為什麼「最小佇列」需要完全不同的機制（5.4 單調佇列）。**同一個統計量，容器的刪除語意一改，方法就得全換。**

**引理 2（155 差值編碼的正確性）。** 設推入 $x$ 時的舊最小值為 $\mu$。

*(a) 哨兵可辨識*：只有在 $x < \mu$ 時才推入 $2x - \mu$。此時 $2x - \mu < x < \mu = $ 更新後的 `mn`... 更精確地說，更新後 `mn` $= x$，而存入的值 $2x - \mu < x$（因 $x < \mu$）。反之，若 $x \ge \mu$，存入的是 $x \ge \mu = $ 更新後的 `mn`。故「存入值 $<$ 當前 `mn`」**恰好**刻畫「這一格是哨兵」，沒有偽陽性也沒有偽陰性。

*(b) 可還原*：哨兵 $v = 2x - \mu$ 且當前 `mn` $= x$，故 $\mu = 2x - v = 2\cdot\texttt{mn} - v$，彈出時據此還原。$\square$

**這個技巧的代價是把值域擴大一倍**——$2x - \mu$ 可能到 $\pm 2^{32}$。**寫 `int` 會 UB，這不是理論顧慮：LeetCode 155 的測資包含 $\pm 2^{31}$ 級的輸入。**

**引理 3（895 最大頻率堆疊）。** 維持兩條不變量：

- (I1) `group[f]` 恰好包含所有「當前次數 $\ge f$」的元素，且每個元素在其中出現的位置對應它**第 $f$ 次被 push 的時刻**（按時間遞增）。
- (I2) `maxF` = 當前所有元素次數的最大值。

*(I1) 的維持*：push $x$ 使其次數變成 $c$，此時且僅此時 $x$ 第 $c$ 次被推入，於是加入 `group[c]`；它在 `group[1..c-1]` 中的紀錄不需變動。pop 時從 `group[maxF]` 取走 $x$ 的最後一筆紀錄並令次數減一，恰好抵銷。

*正確性（彈出的是對的元素）*：pop 要取「次數最大者；若並列，取最靠近棧頂（最晚推入）者」。

由 (I2)，答案的次數是 `maxF`。由 (I1)，`group[maxF]` 中的元素當前次數皆 $\ge$ `maxF`，而 `maxF` 已是最大值，故**恰為 `maxF`**。於是對 `group[maxF]` 中的每個元素 $y$，它的第 `maxF` 次推入就是它的**最後一次**推入。因此 `group[maxF]` 的排列順序（按第 `maxF` 次推入的時間）等同於按「最後一次推入的時間」排序，取尾端就是最晚被推入的那個——正是題目要的並列規則。$\square$

**這個資料結構的巧妙之處在於：它不做任何排序，卻靠「按達到的次數分層」把並列規則自動化了。** 關鍵前提是上一段那句「`group[maxF]` 中的元素次數恰為 `maxF`」——若沒有 (I2)，這句話不成立，尾端就不必然是答案。

*為什麼 `--maxF` 只要減一就夠*：pop 讓某個元素次數從 `maxF` 降到 `maxF - 1`。若 `group[maxF]` 因此變空，表示沒有元素還維持在 `maxF`，而先前所有元素次數 $\le$ `maxF`，故新的最大值恰為 `maxF - 1`（`group[maxF-1]` 必非空，因為剛剛那個元素還在裡面）。**這是為什麼不需要重新掃描求最大值。**

**引理 4（636 的獨佔時間結算）。** 不變量：`st` 由底到頂 = 當前正在執行的呼叫鏈；`prev` = 上一個已結算到的時間點。

- `start id at t`：區間 $[\texttt{prev},\ t-1]$ 屬於當前棧頂（若有），故 `ans[st.back()] += t - prev`；然後 `st.push_back(id); prev = t;`
- `end id at t`：區間 $[\texttt{prev},\ t]$ 屬於棧頂（`end` 的時間戳是**閉的**，該單位時間仍在執行），故 `ans[st.back()] += t - prev + 1; st.pop_back(); prev = t + 1;`

*正確性*：每個單位時間恰好被結算一次，且被結算給「當時位於棧頂的函式」——棧頂正是當時真正在執行（未被子呼叫佔用）的那個函式。**`start` 用半開、`end` 用閉，這個不對稱來自題目的時間戳定義，不是實作偏好；搞混就會系統性地差 1。**

**這個解法依賴一個很強的前提：日誌是良巢狀的**（每個 `end` 對應最近未關閉的 `start`）。堆疊之所以夠用，正是因為巢狀。若允許任意交錯（A 開始、B 開始、A 結束、B 結束），堆疊模型直接崩潰，得改用「事件排序 + 區間拆分」。

**引理 5（1172 的懶刪除）。** `avail` 堆中可能含有「已經被填滿」的堆疊下標（因為填滿時不方便從堆中刪除）。維持較弱的不變量：

> **`avail` 是「所有未滿堆疊下標」的超集合。**

`push` 時反覆 `pop` 堆頂直到找到一個真正未滿的下標（或堆空則新開一個）。**弱不變量 + 使用時驗證**是懶刪除的標準形式，6.6 會專章討論。*攤還正確性*：每個過期項只會被丟棄一次，故總丟棄次數不超過總插入次數。

## 時間與空間複雜度

| 結構 | 操作 | 時間 | 額外空間 |
| --- | --- | --- | --- |
| 155 輔助堆疊 | push/pop/top/getMin | $O(1)$ | $O(n)$ |
| 155 差值編碼 | push/pop/top/getMin | $O(1)$ | $O(1)$ |
| 716 鏈結串列 + `map` | push/pop/top/peekMax/popMax | $O(\log n)$ | $O(n)$ |
| 895 分層 | push/pop | $O(1)$ 攤還 | $O(n)$ |
| 636 | 整體 | $O(\text{logs})$ | $O(\text{depth})$ |
| 1172 懶刪除堆 | push/pop/popAtStack | $O(\log n)$ 攤還 | $O(n)$ |

**895 為什麼是攤還 $O(1)$ 而非最壞 $O(1)$**：`unordered_map` 的雜湊在最壞情況會退化，且 `group[c]` 的 `vector` 有可能觸發重配置。實務上把 `group` 換成 `vector<vector<int>>`（下標即次數，因為次數 $\le$ push 總數）可以去掉雜湊，更快。

**716 為什麼不能 $O(1)$**：`popMax` 需要在任意位置刪除並維持「最大值」可查。這在比較模型下等價於優先佇列，$\Omega(\log n)$ 的下界來自排序下界。**看到「刪除任意位置的極值」就別再想 $O(1)$。**

**155 的兩種寫法怎麼選**：差值編碼省空間但常數更大（每次 top 都要比較與可能的還原），且有溢位陷阱。**$n$ 不大時輔助堆疊更好；面試時先寫輔助堆疊、再口頭補充差值編碼，是最穩的答法。**

## 與相似技巧的比較

- **與 4.1 基礎堆疊**：本節多的是「額外統計量」。判準是：**這個統計量能不能隨 pop 自然回退？** 能（min/max）就同步堆疊；不能（任意刪除）就得配資料結構。
- **與 5.4 單調佇列**：「滑動視窗最小值」是同樣的問題搬到佇列上。因為佇列刪的是最舊元素，前綴最小值無法回退，必須改用「單調雙端佇列」——**同一個查詢，容器換了，方法完全不同**，這個對照最能說明本節開頭那句話。
- **與 5.2 用兩個堆疊實作佇列**：反過來的方向。「最小佇列」的經典解法正是「兩個最小堆疊」——用 4.2 的結構去補 5.x 的不足。
- **與 6.x 堆**：716 與 1172 都用到堆或有序集合。**堆疊只能回退，堆能取極值；需要「任意順序取極值」就必須付 $O(\log n)$。**
- **與 6.6 懶刪除堆**：1172 是懶刪除的預告。**弱不變量（超集合）+ 使用時驗證**這個模式，在 6.6、Dijkstra、以及各種「無法從堆中刪除中間元素」的場合反覆出現。
- **與 895 的替代解法**：也可以用 `priority_queue<tuple<int,int,int>>`（次數、序號、值）$O(\log n)$。**分層法之所以能 $O(1)$，是因為它利用了「次數每次只 $\pm 1$」這個離散結構——與計數排序優於比較排序是同一個道理。**

## 本節重點速查

- **堆疊的獨有性質：LIFO 讓歷史狀態天然保存，統計量可以逐格 $O(1)$ 回退。** 佇列沒有這個性質（要用 5.4 單調佇列）。
- 155 輔助堆疊：`mn[i] = min(st[0..i])`，push/pop 同步。**前提是只從尾端刪除。**
- 155 差值編碼：$x < \mu$ 時存 $2x - \mu$；「存入值 $<$ 當前 `mn`」恰好刻畫哨兵。**一定要 `long long`。**
- 716 需要 `popMax`（挖中間），輔助堆疊失效 ⇒ 鏈結串列 + `map`，$O(\log n)$，且有下界。
- 895 分層：`group[c]` 記錄「第 $c$ 次推入」的時刻順序。因 `group[maxF]` 內元素次數恰為 `maxF`，其尾端就是最晚推入者——**並列規則被結構自動滿足**。`maxF` 只需 $-1$。
- 636：棧頂 = 當前實際執行者；**`start` 結算 $t - \texttt{prev}$、`end` 結算 $t - \texttt{prev} + 1$**，不對稱來自時間戳定義。**前提是日誌良巢狀。**
- 1172：懶刪除，維持「`avail` 是未滿下標的超集合」這條**弱不變量**，使用時再驗證。
- 設計題的通用問法：**這個量能否隨 pop 自然回退？** 能 ⇒ 同步堆疊 $O(1)$；不能 ⇒ 配堆或有序集合 $O(\log n)$。
