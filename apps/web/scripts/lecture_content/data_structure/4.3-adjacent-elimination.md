## 這個技術解決什麼問題

一類題目長成這樣：**「只要相鄰的兩個（或 $k$ 個）元素滿足某條件就把它們刪掉，刪完之後左右接起來可能又形成新的可刪對，重複直到不能刪為止。」**

1047（刪除字串中的所有相鄰重複項）刪相鄰相同字元；1544（整理字串）刪相鄰的大小寫配對；1003（檢查替換後的詞是否有效）刪子串 `abc`；1209 刪 $k$ 個相鄰相同；735（行星碰撞）刪掉碰撞中較小的行星。

暴力是「掃一遍找到一處就刪，然後從頭再掃」，每次刪除 $O(n)$、最多刪 $O(n)$ 次，$O(n^2)$。

堆疊把它壓成 $O(n)$，關鍵是一個結構性事實：**刪除之後新產生的左鄰居，恰好就是棧頂。** 於是「回頭找新的可刪對」這件事變成 $O(1)$ 的 `st.back()`。

但在寫程式之前，有一個**必須先問清楚的問題**：由左至右、每次只跟棧頂比對，得到的結果和「以其他順序刪除」得到的結果，一定相同嗎？如果不同，貪心就沒有意義。下一節會證明：對大部分題目答案是「相同」，而對少數題目（1717）答案是「不同，而且順序決定分數」。

## 狀態／資料結構定義

**標準骨架（1047、1544、1003、2696）**：一個堆疊，掃描時
```
for each x in s:
    if (堆疊非空 && 可以與棧頂消除) 彈出棧頂（並丟棄 x）
    else 推入 x
```
字串題直接用 `std::string` 當堆疊，最後不必反轉。

**消除條件依題而異，這是唯一要改的地方**：

| 題目 | 消除條件 | 消除動作 |
| --- | --- | --- |
| 1047 | `x == st.back()` | 彈出棧頂，丟棄 `x` |
| 1544 | `(x ^ st.back()) == 32`（同字母異大小寫） | 同上 |
| 2696 | 棧頂為 `A` 且 `x == 'B'`（或 `C`/`D`） | 同上 |
| 1003 | `x == 'c'` 且棧頂兩格為 `"ab"` | 彈出兩格 |
| 1209 | `x == st.back().ch` 且計數達 $k$ | 整組彈出 |

**1209 需要壓縮表示**：堆疊元素是 `pair<char,int>`（字元 + 連續出現次數），而不是單一字元。推入時若與棧頂同字元則 `++count`，`count == k` 時整組彈出。**用「字元 + 次數」而非「$k$ 個字元」是為了讓 $k$ 很大時仍是 $O(n)$ 空間，也讓判定變成 $O(1)$ 比較而非 $O(k)$。**

**735 行星碰撞的堆疊語意不同**：堆疊裡放的是「已經穩定、彼此永遠不會再碰撞」的行星。正號表示向右、負號表示向左。推入新行星時要用 `while` 迴圈連續處理（一顆左行行星可能連撞掉好幾顆右行行星），且有三種結局（新的被撞毀 / 棧頂被撞毀 / 兩者同歸於盡），**必須用一個 `alive` 旗標或 `goto`-free 的結構清楚表達，否則很容易漏掉「新行星已毀就不該推入」這一支。**

## 不變量或正確性證明

### 定理 1（消除的合流性：結果與刪除順序無關）

這是本節所有貪心解法的地基。用改寫系統的語言：把「刪除一處」看成一步改寫 $S \to S'$。

**（終止性）** 每一步都讓字串長度嚴格變短，故任何改寫序列都會在 $\le n$ 步內停在一個**不可再改寫**的字串（範式）。

**（局部合流性）** 若 $S$ 有兩處不同的可刪位置 $R_1 \ne R_2$，需證：分別刪除後，兩個結果都能繼續改寫到同一個字串。

- *情形 A：$R_1$ 與 $R_2$ 不相交。* 刪掉其中一個不影響另一個仍然可刪（它的兩個元素仍相鄰），故兩邊都能再刪另一個，結果相同。**注意這裡用到「刪除只會讓兩側接合，不會拆散未被刪的相鄰關係」。**
- *情形 B：$R_1$ 與 $R_2$ 重疊。* 這時要逐題檢查。1047 的重疊只可能是 `aaa`（位置 $(0,1)$ 與 $(1,2)$），刪任一者都得到 `a` ✔。1209（刪 $k$ 個相同）的重疊是 $k+1$ 個以上的同字元連續段，刪任一段結果相同 ✔。**1003 的 `abc` 根本不可能重疊**——因為 `abc` 沒有非空的「既是真前綴又是真後綴」的邊界（border），兩個出現位置必定不交 ✔。2696 的 `AB`、`CD` 字母互不相同，同理不交 ✔。

由 Newman 引理（終止 + 局部合流 $\Rightarrow$ 合流），**範式唯一**。$\square$

**推論：任何「總是刪得到就刪」的策略都會得到同一個答案，於是由左至右的堆疊掃描是正確的。**

**這條定理點名了它依賴的前提：情形 B 必須逐題驗證。** 「重疊時殘留相同」不是普遍成立的性質——1717 就是反例（見定理 3）。**看到新的消除規則，第一件事是問「兩處消除可以重疊嗎？重疊時刪哪個都一樣嗎？」而不是直接套堆疊模板。** 一個現成的判準：**若被刪的模式串沒有非空 border（是「無邊界字串」），兩處出現必定不相交，情形 B 自動不存在。**

### 定理 2（堆疊掃描的不變量）

處理完前綴 $s[0..i-1]$ 後，**堆疊內容 = 該前綴獨自化簡到底所得的範式**。

*證明（歸納）。* 基底：空前綴對應空堆疊。歸納步：設堆疊 $T$ 是 $s[0..i-1]$ 的範式（即 $T$ 內部已無可刪處）。加入 $s_i$ 後，新字串 $T\,s_i$ 中**唯一可能的可刪處必然含 $s_i$**（因為 $T$ 內部無可刪處），也就是「$s_i$ 與 $T$ 的尾端」。若可刪則刪，刪完後尾端又可能與 $s_i$ 的新左鄰形成可刪處（1003、1209 用 `while` 處理），反覆直到不可刪；此時得到的正是 $T\,s_i$ 的範式，由定理 1 它也就是 $s[0..i]$ 的範式。$\square$

**「$T$ 內部已無可刪處，所以只要檢查尾端」——這一句就是為什麼掃描是 $O(n)$ 而不是每次重掃 $O(n^2)$。**

### 定理 3（735 行星碰撞：堆疊的形狀不變量）

行星碰撞**不是**對稱的消除：只有「左邊向右飛、右邊向左飛」才會相撞（`+` 在左、`-` 在右）。

**不變量**：堆疊內容由底到頂形如「一段負數（向左飛）接一段正數（向右飛）」，即 $-,-,\dots,-,+,+,\dots,+$。

*維持*：一顆負數行星若出現在正數之上，兩者必定相撞（左邊的正數向右、上面的負數向左），演算法會處理掉，不可能留下。

*推論*：**堆疊內部永遠不會有待處理的碰撞**，所以新行星只需要與棧頂互動。若新行星為正，它在最右且向右飛，與棧頂（正數向右，或負數向左）都在遠離，直接推入；若為負，它會與所有棧頂的正數依序相撞，用 `while` 處理到棧空、棧頂為負、或它自己被撞毀為止。$\square$

**這條不變量比定理 2 更強也更具體：它不只說「無可刪處」，還說出了堆疊的具體形狀。** 有了它，三種碰撞結局的處理就有明確的終止條件，不會寫成一團 `if` 巢狀。

### 定理 4（1717：不合流的消除，順序決定分數）

刪 `ab` 得 $x$ 分、刪 `ba` 得 $y$ 分。**這兩種消除會重疊**：`aba` 中位置 $(0,1)$ 是 `ab`、位置 $(1,2)$ 是 `ba`，定理 1 的情形 B 不再自動成立。

*但重疊時的殘留相同*：`aba` 刪 `ab` 剩 `a`，刪 `ba` 也剩 `a`；`bab` 刪 `ab` 剩 `b`，刪 `ba` 也剩 `b`。**兩種選擇留下的字串完全一樣，差別只在得分。**

*推論（貪心的正確性）*：設 $x \ge y$。任何時刻若兩種消除重疊，選 `ab` 得分較高而後續狀態相同，故不劣；若不重疊，由情形 A 順序無關。因此「先用一次堆疊掃描消光所有 `ab`，再用一次掃描消光所有 `ba`」是最優的。$\square$

**這個對照才是本節真正的重點**：1047 那類題目「順序無關」是一條**需要證明的定理**，不是理所當然；而 1717 恰好是它失效的地方，於是必須另外提供一個交換論證。**兩者的程式碼幾乎一樣，正確性的來源卻完全不同。**

## 時間與空間複雜度

**時間 $O(n)$。** 每個元素最多推入一次、彈出一次（1209 的計數合併只讓推入更少），內層 `while` 的總執行次數受總彈出次數限制，攤還後仍是 $O(n)$。

**空間 $O(n)$**，最壞情況沒有任何消除（例如 `abcdef` 之於 1047）。

**1209 的空間**：用 `pair<char,int>` 壓縮後仍是 $O(n)$，但**當輸入是 $10^5$ 個相同字元、$k = 10^5$ 時，壓縮版只用 1 格，未壓縮版用 $10^5$ 格**。時間上，未壓縮版每次判定要看 $k$ 格（或維護額外計數），壓縮版恆為 $O(1)$。

**735 的攤還**：每顆行星最多被推入一次、被撞毀一次。內層 `while` 可能一次撞掉多顆，但總撞毀數 $\le n$，故 $O(n)$。

**與暴力的落差**：$O(n^2) \to O(n)$。$n = 10^5$ 時 $10^{10} \to 10^5$。

## 與相似技巧的比較

- **與 4.1 基礎堆疊**：4.1 的「抵銷」（844 退格）是本節的最簡特例——消除規則不看內容，只看「有沒有 `#`」。**因此 844 能退化成計數器，而 1047 不行（要記住是哪個字元）。**
- **與 4.4 括號**：括號匹配也是相鄰消除（`()` 消掉），且 `()` 無 border，情形 B 不存在，合流性自動成立。**4.4 之所以能用「計數器」解單一種括號，是因為所有左括號同質；多種括號就必須用堆疊記住種類。**
- **與 4.7 單調堆疊**：兩者都在推入前用 `while` 彈出棧頂，形狀極像，但**目的相反**：本節彈出是為了「刪掉不再需要的元素」，單調堆疊彈出是為了「結算被彈出元素的答案」。**看到 `while (!st.empty() && cond) st.pop_back();` 先問：彈出的東西是被丟棄，還是在被結算？**
- **與 KMP／字串匹配**：定理 1 情形 B 的判準「模式串有沒有 border」正是 KMP 失敗函數在算的東西。**無 border ⇒ 兩處出現不重疊 ⇒ 合流性免驗。**
- **與遞迴下降**：1003 也可以用「反覆 `s.find("abc")` 並刪除」實作，$O(n^2)$；堆疊版把它壓成 $O(n)$。
- **與 3561（相鄰字元消除的變體）與 2751（機器人碰撞）**：2751 是 735 的加權版（多了健康值），堆疊不變量完全一樣，只是碰撞結算規則變複雜。**認出 735 的形狀不變量，2751 就只是換算術。**

## 本節重點速查

骨架：由左至右掃描，**能與棧頂消除就消，否則推入**；字串題用 `std::string` 當堆疊。
**核心不變量（定理 2）**：堆疊內容 = 已處理前綴的範式；因為內部已無可刪處，**只需檢查棧頂**，這就是 $O(n)$ 的來源。
**合流性（定理 1）是需要證明的**：終止性顯然，局部合流要檢查「兩處消除重疊時，刪哪個都一樣嗎」。**模式串無 border ⇒ 不可能重疊 ⇒ 免驗**（`abc`、`AB`、`()`）。
1047 的重疊是 `aaa`、1209 是 $k+1$ 段連續，兩者都殘留相同 ✔。
**1717 是反例**：`ab` 與 `ba` 會重疊，順序影響分數；但重疊時殘留相同，故「先消分數高的那種」最優——**同樣的程式碼，不同的正確性論證。**
1209 用 `pair<char,int>` 壓縮，判定 $O(1)$、極端輸入省空間。
735 的不變量是**形狀**：堆疊由底到頂 = 負數段 + 正數段，故內部無待處理碰撞；新行星只跟棧頂互動，`while` 處理連環撞，記得用 `alive` 旗標避免「已毀還推入」。
攤還 $O(n)$：每個元素最多進出各一次，內層 `while` 不影響總量。
