## 這個技術解決什麼問題

佇列（queue）是 **FIFO：先進先出**。它處理的是「**順序必須被保留、而且只從兩端動**」的問題：

- **時間視窗**：933（最近的請求次數）、362（敲擊計數器）、346（資料流中的移動平均）——過期的元素一定是最早進來的那些，所以只要從頭端丟。
- **輪轉／循環**：649（Dota2 參議院）、950（按遞增順序顯示卡牌）——「輪到誰」本身就是佇列。
- **層序遍歷 / BFS**：所有「最少步數且每步代價相同」的題。
- **資源池**：379（電話目錄管理系統）——可用資源排隊等待分配。
- **帶惰性刪除的「第一個滿足條件者」**：1429（第一個唯一數字）。

**它和堆疊的差別不只是「另一端」。** 堆疊保留的是**巢狀歷史**（4.2），佇列保留的是**到達順序**。一旦題目說「先來先服務」「按原順序」「一層一層」，答案就是佇列。

**反過來的辨識訊號**：如果你發現自己在用 `vector` 的 `erase(begin())`（$O(n)$）反覆刪頭，那就該換成佇列或雙指標。

## 狀態／資料結構定義

**C++ 的三種選擇：**

| 型別 | 頭部彈出 | 隨機存取 | 可遍歷 | 適用 |
| --- | --- | --- | --- | --- |
| `std::queue<T>`（底層 `deque`） | $O(1)$ | ✗ | ✗ | 語意最清楚的純 FIFO |
| `std::deque<T>` | $O(1)$ | ✓ | ✓ | 需要看中間元素、或兩端都要動 |
| `vector<T>` + `head` 指標 | $O(1)$ 攤還 | ✓ | ✓ | 需要保留全部歷史（如 BFS 回溯路徑） |

**選型判準**：**需要在彈出後仍然讀到已彈出的元素，就用 `vector` + `head`**（例如 BFS 結束後要沿 `parent` 回溯，或 649 需要下標）。只進不回頭就用 `queue`。

**兩種常見的封裝：**

1. **視窗佇列**：`queue<int> q;`，狀態是「所有仍在視窗內的事件時間戳」。加入新事件後，`while (!q.empty() && q.front() <= t - W) q.pop();`。答案就是 `q.size()`（933、362）。
2. **增量統計佇列**：除了佇列本身，另外維護一個聚合量（`sum`、`cnt`）。彈出時扣除、加入時累加，使查詢 $O(1)$（346）。

**BFS 的兩種寫法**：

- **不分層**：`q` 存 `(node, dist)` 或另開 `dist[]` 陣列。
- **分層**：`for (int sz = q.size(); sz--; )` 一次處理完整層。**`sz` 必須在迴圈開始前快照**，否則本層新推入的節點會被算進本層。

## 不變量或正確性證明

### 定理 1（視窗佇列：為什麼只要從頭端丟）

933／362 的不變量是：**每次操作結束後，`q` 恰好等於集合 $\{t' : t' \text{ 已發生且 } t' > t - W\}$，且由頭到尾遞增。**

*證明*：由歸納。加入 $t$ 時先 push 再 pop。
- *遞增性*：依賴**前提「時間戳單調不減」**（題目保證 `ping` 的參數嚴格遞增）。既然 $t \ge$ 所有已存元素，push 後仍遞增。
- *剛好丟掉該丟的*：由遞增性，過期元素（$t' \le t - W$）構成一個**前綴**。所以「反覆彈頭直到頭端不過期」剛好移除全部過期元素、不會誤傷。$\square$

**這條定理完全依賴「時間戳單調」這個前提。** 若事件可能亂序抵達（例如亂序的日誌），過期元素就不再是前綴，必須改用 `multiset` 或樹狀陣列（9.x），複雜度升為 $O(\log n)$。**這是佇列能用與不能用的分界線，值得每次都確認一次。**

*推論（346 移動平均）*：`sum` 隨 push／pop 增減，任一時刻 `sum` $=$ 佇列元素之和。**用 `double` 累加會有浮點誤差累積**（加了又減，殘差不會自動抵銷）；若元素是整數，`sum` 應宣告為 `long long`，最後才除。

### 定理 2（BFS 的層序不變量）

**在 BFS 的任一時刻，佇列中的節點距離只可能取兩個相鄰值 $d$ 與 $d+1$，且所有 $d$ 排在所有 $d+1$ 前面。**

*證明（歸納）*。初始只有源點（距離 0）。設當前不變量成立，佇列為 $[d,\dots,d,\,d+1,\dots,d+1]$。彈出頭端（距離 $d$）並推入它的未訪問鄰居（距離 $d+1$），推到尾端——仍是「若干 $d$ 後接若干 $d+1$」。當所有 $d$ 被彈完，佇列變成純 $d+1$，形態退化為 $[d+1,\dots]$，不變量對 $(d+1, d+2)$ 繼續成立。$\square$

*推論*：**節點按距離非遞減的順序出隊**，所以第一次訪問到終點時的距離就是最短距離。**這個推論依賴「每條邊權重相同」**；邊權不同就必須換成 Dijkstra（優先佇列，6.x）。

*推論 2*：`for (int sz = q.size(); sz--; )` 這一圈處理的恰好是距離 $d$ 的全部節點——這就是分層寫法成立的理由。

### 定理 3（649 Dota2 參議院：貪心 + 雙佇列）

兩派輪流行動，每個議員可以禁掉一名對方議員；求哪一派獲勝。

*宣稱*：**輪到某議員時，禁掉「循環順序上排在他後面、最近的一名對手」是最優的。**

*證明（交換論證）*。設當前議員屬 R，他有兩個選擇：禁最近的對手 $x$，或禁更遠的對手 $y$。
- 禁 $x$：$y$ 仍在，但在本輪中 $y$ 行動的時機晚於 $x$ 原本的時機。
- 禁 $y$：$x$ 仍在，$x$ 會在**更早**的時刻行動並禁掉一名 R。

把「禁 $x$」的後續策略平移到「禁 $y$」的局面上，R 方在「禁 $y$」的局面下至少要多承受一次來自 $x$ 的即時打擊，而所得（$y$ 被移除）在時序上更晚才有價值。故禁 $x$ 不劣。$\square$

*實作對應*：用兩個佇列 `qR`、`qD` 存各派議員的**下標**（初始已按下標遞增）。每回合比較兩隊頭端 $i_R$、$i_D$：**下標小者行動**，禁掉對方的頭端（直接 `pop`），自己則以 `i + n` 重新入隊。

*不變量*：**兩個佇列各自遞增，且兩隊頭端的較小者就是「全域下一個行動的人」。** 加上 `n` 再入隊，等價於把他放到下一輪的相同相對位置——這保持了循環順序。任一佇列空掉時，另一派獲勝。

### 定理 4（1429 第一個唯一數字：惰性刪除的弱不變量）

維護 `queue<int> q` 與 `unordered_map<int,int> cnt`。`add(x)` 時 `cnt[x]++` 並 `q.push(x)`；`showFirstUnique()` 時 `while (!q.empty() && cnt[q.front()] > 1) q.pop();`。

*不變量（弱）*：**`q` 是「所有仍唯一的數字，按首次加入順序排列」的一個超集合**，且非唯一元素只可能堆積在前段（因為一旦某元素變成非唯一，它永遠不會再變回唯一——`cnt` 只增不減）。

*正確性*：由「`cnt` 單調不減」這個**前提**，「唯一」是一個**單向失效**的性質。因此彈頭清理是安全的：被彈掉的元素永遠不會再需要。清理後的頭端若存在，就是最早加入且仍唯一者。$\square$

**「弱不變量 + 單向失效」是惰性刪除的通用模式**，4.2 的 1172、6.6 的延遲刪除堆都是同一招。**它的前提永遠是：被判定失效的元素不會復活。**

### 定理 5（950 按遞增順序顯示卡牌：逆向模擬）

正向難以直接構造，改成**把輸出過程反過來跑**：把牌值由大到小處理，每步先「把佇列尾端搬到頭端」再「把當前牌壓到頭端」。

*證明*：正向操作是「取頭端輸出、再把新的頭端移到尾端」。其逆操作恰為「把尾端移到頭端、再在頭端插入」。由歸納，反向跑完 $n$ 步得到的排列，正向執行必產生遞增輸出。$\square$

**「正向難、逆向易」在模擬題中很常見；判準是原操作是否可逆。** 這裡每一步都是雙射，所以可逆。

## 時間與空間複雜度

| 操作 | `std::queue` / `deque` |
| --- | --- |
| `push` / `pop` / `front` / `size` | $O(1)$ |
| 遍歷 | $O(n)$（`queue` 不支援，須換 `deque`） |

**視窗佇列（933、362）**：單次 `ping` 最壞 $O(n)$（一次清掉大量過期元素），但**攤還 $O(1)$**——每個元素只入隊一次、出隊一次，位能論證與 4.7 定理 4 完全相同。**$q$ 次操作總計 $O(q)$。** 空間 $O(W)$ 級（視窗內的事件數）。

**BFS**：$O(V + E)$ 時間、$O(V)$ 空間。**注意 `visited` 必須在「入隊時」標記，不是「出隊時」**，否則同一節點可能被推入多次，最壞退化到 $O(V^2)$ 甚至指數。

**649**：每回合至少移除一人，故總回合數 $< n$；每回合 $O(1)$。總計 $O(n)$，空間 $O(n)$。

**1429**：`add` 為 $O(1)$；`showFirstUnique` 攤還 $O(1)$（每個元素最多被彈一次）。

**950**：排序 $O(n\log n)$ 主導，模擬 $O(n)$。

**常數提醒**：`std::queue` 預設底層是 `std::deque`，配置是分塊的，比 `vector` 稍慢但支援 $O(1)$ 頭部彈出。**在極度追求常數的場合（BFS 上百萬節點），改用 `vector<int> q; int head = 0;` 通常快 2–3 倍**，代價是記憶體不回收——但那正好讓你能事後遍歷全部訪問順序。

## 與相似技巧的比較

- **與 4.x 堆疊**：**LIFO 保留巢狀結構，FIFO 保留到達順序。** 「括號、遞迴、回溯、最近的未匹配者」用堆疊；「排隊、層序、最短步數、最早的未過期者」用佇列。**用堆疊做 BFS 會變成 DFS，這是最常見的張冠李戴。**
- **與 5.3 雙端佇列**：`deque` 是佇列的超集。**只在真的需要「兩端都增刪」時才用**——用 `deque` 寫純 FIFO 沒有錯，但用 `queue` 更能向讀者宣告意圖。
- **與 5.4 單調佇列**：單調佇列在 FIFO 的基礎上，額外從**尾端**淘汰「劣勢元素」。**普通佇列保留全部，單調佇列只保留可能成為答案的候選。**
- **與 2.x 滑動視窗（雙指標）**：本節的視窗佇列本質就是滑動視窗。**當「視窗內容」可以只用左右指標與若干聚合量表示時，用雙指標（$O(1)$ 空間）；當你需要真的枚舉／彈出視窗內的個別元素時，用佇列。**
- **與 6.x 優先佇列**：優先佇列按「優先級」出隊，佇列按「到達時間」出隊。**題目若說「每步代價相同」用佇列（BFS）；「代價不同」用優先佇列（Dijkstra）。** 0-1 邊權則用雙端佇列 BFS（5.3），這是三者之間的橋樑。
- **與環形陣列（5.2 的 622）**：固定容量時，用 `vector` + 頭尾下標取模可以完全避免動態配置。**上限已知就用環形陣列，未知就用 `deque`。**

## 本節重點速查

**佇列 = 保留「到達順序」；堆疊 = 保留「巢狀歷史」。** 看到「先來先服務／層序／最少步數（等權）」就是佇列。
**視窗佇列（定理 1）成立的前提是「時間戳單調不減」**——過期元素才會構成前綴，才能只從頭端丟。亂序輸入必須改用 `multiset` / 樹狀陣列。
**攤還 $O(1)$**：每個元素只入隊一次、出隊一次，位能論證同 4.7 定理 4。**`for` 裡的 `while` 不代表 $O(n^2)$。**
**BFS 不變量（定理 2）**：佇列中只有兩個相鄰距離、且小的在前 ⇒ 出隊順序按距離非遞減 ⇒ 首次到達即最短。**前提是邊權相同。**
**BFS 的 `visited` 在「入隊」時標記，不是出隊時。** 分層時 `sz = q.size()` 必須先快照。
**649**：雙佇列存下標，下標小者先行動、禁對方頭端、自己 `+n` 重新入隊；貪心「禁最近對手」由交換論證保證最優。
**惰性刪除（1429）的通用前提**：判定失效後不會復活（`cnt` 只增不減）。同模式見 4.2 的 1172、6.6。
**選型**：需要事後回讀已彈出的元素 ⇒ `vector` + `head`；純 FIFO ⇒ `queue`；兩端都動 ⇒ `deque`；容量固定 ⇒ 環形陣列。
