## 這個技術解決什麼問題

序列中間的插入與刪除很貴：`std::vector` 要搬動後方一整段，$O(n)$；$q$ 次操作就是 $O(nq)$。2296（設計一個文字編輯器）有 $2\times10^5$ 次操作、文字長度也到 $2\times10^5$，暴力必定超時。

**對頂結構的觀察是：如果所有操作都發生在「同一個移動中的分界點」附近，就把序列從分界處剖成兩半，各自用一個堆疊裝，讓分界點永遠位於兩個棧頂之間。**

於是：
- 在分界處插入 / 刪除 = 對左棧 `push_back` / `pop_back`，$O(1)$；
- 分界點左移 / 右移一格 = 從一個棧頂搬一個元素到另一個棧頂，$O(1)$。

原本 $O(n)$ 的中間操作全變成棧頂操作。這個結構在文字編輯器裡叫 **gap buffer**（間隙緩衝區），是真實編輯器（Emacs）用了幾十年的資料結構。

**同一個想法換一個排序維度就是「對頂堆」**：分界不再是「位置」而是「大小」，兩個堆各裝一半，堆頂之間就是中位數（295、480、1825）。**「把序列從關鍵分界剖成兩半，讓昂貴的操作退化成端點操作」——這句話才是本節的內容，堆疊只是其中一種實現。**

## 狀態／資料結構定義

**對頂堆疊（2296）**
- `std::string left`：游標**左側**的文字，由底到頂 = 由左到右（**順序**）。
- `std::string right`：游標**右側**的文字，由底到頂 = 由右到左（**逆序**）。
- 完整文字 $= \texttt{left} + \mathrm{reverse}(\texttt{right})$；游標恰在兩者之間。

用 `std::string` 而非 `std::stack<char>`：`push_back`／`pop_back`／`back` 齊全，且連續記憶體、可 `substr`，最後回傳「游標左邊最多 10 個字元」時直接 `left.substr(...)`。

**四個操作**

| 操作 | 實作 | 成本 |
| --- | --- | --- |
| `addText(t)` | 逐字 `left.push_back` | $O(\lvert t\rvert)$ |
| `deleteText(k)` | 從 `left` 尾端刪 $\min(k, \lvert\texttt{left}\rvert)$ 個 | $O(\min(k, \lvert\texttt{left}\rvert))$ |
| `cursorLeft(k)` | 搬 $\min(k, \lvert\texttt{left}\rvert)$ 個字元 `left` → `right` | 同上 |
| `cursorRight(k)` | 搬 $\min(k, \lvert\texttt{right}\rvert)$ 個字元 `right` → `left` | 同上 |

四個操作都回傳「游標左邊最多 10 個字元」，即 `left.substr(left.size() - min<size_t>(10, left.size()))`。

**注意 `right` 是逆序存放**，這是整個結構的關鍵設計：只有逆序，游標右移才會是「從 `right` 的棧頂取」；若順序存放，右移就得從 `right` 的**頭部**取，退化成 $O(n)$。

**對頂堆（中位數，295）**
- `priority_queue<int> lo`（大根堆）裝較小的一半；`priority_queue<int, vector<int>, greater<>> hi`（小根堆）裝較大的一半。
- 大小約束：$\lvert\texttt{lo}\rvert = \lvert\texttt{hi}\rvert$ 或 $\lvert\texttt{lo}\rvert = \lvert\texttt{hi}\rvert + 1$。
- 中位數：奇數個時 `lo.top()`，偶數個時 $(\texttt{lo.top()} + \texttt{hi.top()})/2$。

## 不變量或正確性證明

### 定理 1（對頂堆疊的表示不變量）

**不變量 (I)**：$\text{文字} = \texttt{left} + \mathrm{reverse}(\texttt{right})$，且游標位置 $= \lvert\texttt{left}\rvert$。

*維持*：逐操作檢查。

- `addText(t)`：語意是在游標處插入 $t$ 並把游標移到 $t$ 之後。新文字 $= \texttt{left} + t + \mathrm{reverse}(\texttt{right})$，新游標 $= \lvert\texttt{left}\rvert + \lvert t\rvert$。實作把 $t$ 逐字接到 `left` 尾端，恰好得到 (I) ✔
- `deleteText(k)`：刪掉游標左邊 $\min(k, \lvert\texttt{left}\rvert)$ 個字元；`left` 尾端就是游標左邊最近的字元，故 `pop_back` 正確 ✔
- `cursorLeft(k)`：游標左移一格意即「原本在游標左邊最近的字元，現在變成游標右邊最近的字元」。`left.back()` 搬到 `right` 的尾端；由於 `right` 是**逆序**，其尾端正是「游標右邊最近的」，故 (I) 保持 ✔
- `cursorRight(k)`：對稱 ✔

$\square$

**這條不變量點名了它依賴的前提：所有插入與刪除都發生在游標處。** 若題目允許「刪除第 $j$ 個字元」這種與游標無關的隨機位置操作，兩個堆疊就得先把游標移過去，單次 $O(n)$，優勢消失——**那時要換平衡樹（10.1 Splay）或塊狀鏈表。** 對頂結構的全部價值建立在「操作具有局部性」這個假設上。

### 定理 2（複雜度：為什麼這是「攤還」而不是「每次 $O(1)$」）

游標移動 $k$ 格要搬 $k$ 個字元，**單次並非 $O(1)$**。整體複雜度是

$$O\Big(\sum_{\text{各次操作}} \min(k_i,\ \text{可移動量})\Big) \;\le\; O\Big(\sum_i k_i\Big).$$

2296 的約束保證「所有操作的 $k$ 與文字長度總和 $\le 2\times10^5$」，故總成本線性於輸入規模。

**$\min$ 這個夾取不只是防越界，它是複雜度論證的一部分**：若使用者呼叫 `cursorLeft(10^9)` 而文字只有 10 個字元，實際只搬 10 次。**沒有這個夾取，程式不只會越界，複雜度上界也不再成立。**

*對照*：用 `std::list<char>` + 迭代器當游標，插入／刪除是真正的 $O(1)$，但游標移動仍是 $O(k)$（要逐個 `++it`），而且節點分散、快取表現差好幾倍。**兩者的漸近複雜度相同，對頂堆疊贏在常數。**

### 定理 3（對頂堆的分割不變量與插入正確性）

**不變量**：
- (P1) $\max(\texttt{lo}) \le \min(\texttt{hi})$（每個小半邊的元素都不大於每個大半邊的元素）；
- (P2) $\lvert\texttt{lo}\rvert - \lvert\texttt{hi}\rvert \in \{0, 1\}$。

**插入 $x$ 的標準寫法**（順序不可交換）：
```
lo.push(x);                      // 先無條件丟進 lo
hi.push(lo.top()); lo.pop();     // 把 lo 的最大值移到 hi
if (hi.size() > lo.size()) { lo.push(hi.top()); hi.pop(); }   // 平衡
```

*(P1) 的維持證明*：設插入前 (P1) 成立，記 $L = \texttt{lo}$、$H = \texttt{hi}$，$\max L \le \min H$。

第一步後 `lo` $= L \cup \{x\}$；令 $m = \max(L \cup \{x\})$。第二步把 $m$ 移到 `hi`。

- 新的 `lo` $= (L\cup\{x\})\setminus\{m\}$。若 $m = x$，則新 `lo` $= L$，$\max L \le \min H \le \min(H\cup\{m\})$ ✔
- 若 $m \in L$，則新 `lo` $= (L\setminus\{m\})\cup\{x\}$。$\max(L\setminus\{m\}) \le \max L \le \min H$ ✔；而 $x \le m = \max L \le \min H$ ✔

兩種情形都得 $\max(\text{新 lo}) \le \min H \le \min(H \cup \{m\})= \min(\text{新 hi})$。第三步只是把 `hi` 的最小值搬回 `lo`，$\min H' \le \min(H'\setminus\{\min H'\})$ 且它 $\ge \max(\text{lo})$，(P1) 仍成立。$\square$

**「先丟進 `lo`、再把 `lo` 的最大值移給 `hi`」這個繞路是必要的。** 直覺寫法「$x \le \texttt{lo.top()}$ 就放 `lo`，否則放 `hi`」也對，但需要額外處理 `lo` 為空的情形，而且平衡邏輯要分四種分支。**上面那個三行寫法無分支、無空堆特判，正確性就是上面這段證明。**

*中位數的正確性*：由 (P1)，`lo` 恰是整體最小的 $\lvert\texttt{lo}\rvert$ 個元素。由 (P2)，總數 $n$ 為奇數時 $\lvert\texttt{lo}\rvert = (n+1)/2$，故 `lo.top()` 是第 $\lceil n/2\rceil$ 小 = 中位數；$n$ 為偶數時 $\lvert\texttt{lo}\rvert = \lvert\texttt{hi}\rvert = n/2$，中位數是第 $n/2$ 與第 $n/2+1$ 小的平均，即 `(lo.top() + hi.top()) / 2.0`。$\square$

**溢位提醒**：`(lo.top() + hi.top()) / 2.0` 在兩者皆為 $\pm2^{31}$ 級時，`int` 相加會溢位。**寫成 `(lo.top() + 0.0 + hi.top()) / 2` 或先轉 `long long`。**

*480（滑動視窗中位數）的額外難點*：要刪除離開視窗的元素，但堆不支援任意刪除。**解法是懶刪除（6.6）**——維護一個「待刪除計數表」，只在元素浮到堆頂時才真正丟棄，同時用兩個計數器追蹤兩邊的「有效大小」。**這是本節與 6.6 的接點。**

## 時間與空間複雜度

| 結構 | 操作 | 時間 | 空間 |
| --- | --- | --- | --- |
| 對頂堆疊 | 游標處插入／刪除 | $O(1)$（每字元） | $O(n)$ |
| 對頂堆疊 | 游標移動 $k$ | $O(\min(k, \text{可移動量}))$ | — |
| 對頂堆疊 | 2296 整體 | $O(\sum k_i + \sum \lvert t_i\rvert)$ | $O(n)$ |
| `std::list` + 迭代器 | 同上 | 相同漸近，常數差數倍 | $O(n)$（額外指標） |
| 平衡樹 / 塊狀鏈表 | 任意位置插入刪除 | $O(\log n)$ / $O(\sqrt n)$ | $O(n)$ |
| 對頂堆 | 插入 / 查中位數 | $O(\log n)$ / $O(1)$ | $O(n)$ |
| 對頂堆 + 懶刪除（480） | 滑動一步 | 攤還 $O(\log n)$ | $O(n)$ |

**對頂堆疊沒有 $\log$**，這是它相對平衡樹的最大優勢；代價是**只能在一個移動中的分界點附近操作**。**看到「游標」「當前位置」「分界」這種字眼就想它；看到「任意位置」就放棄它。**

**2296 每次操作回傳字串**：回傳長度上限 10，故不影響漸近複雜度；但**不要每次都建立整個文字再截尾**，那會是 $O(n)$ 每次。

## 與相似技巧的比較

- **與 4.1／4.2 單一堆疊**：單一堆疊只有一個端點，只能表達「最近的」。對頂結構有**兩個**端點夾住一個分界，能表達「分界兩側」。
- **與 5.3 雙端佇列**：`deque` 也是兩端可操作，但它的兩端是**序列的頭尾**；對頂堆疊的兩個棧頂是**序列中間的同一個位置**。**用途完全不同：`deque` 處理「首尾」，對頂處理「中間」。**
- **與對頂堆（295、480、1825、703）**：同一個「剖成兩半」的想法，分界從**位置**換成**大小**。**位置分界 ⇒ 堆疊（$O(1)$）；大小分界 ⇒ 堆（$O(\log n)$），因為大小關係需要維護有序性。**
- **與 6.3 第 K 小／大**：703（資料流中第 K 大）是對頂堆的退化版——只需要一個大小固定為 $K$ 的小根堆，另一半根本不用存。**當只查一側時，另一側可以丟掉。**
- **與 10.1 平衡樹（Splay）**：平衡樹支援任意位置的插入刪除與分裂合併，$O(\log n)$。**對頂堆疊是它在「操作具有局部性」時的 $O(1)$ 特化。** 局部性一旦失效（隨機位置操作），就得付出 $\log$。
- **與 6.6 懶刪除堆**：對頂堆遇到「要刪除任意元素」（480 滑動視窗）時必須配懶刪除，因為 `priority_queue` 沒有 `erase`。

## 本節重點速查

- 核心想法：**把序列從關鍵分界剖成兩半，讓昂貴的中間操作退化成兩個端點操作。**
- 2296 的不變量：文字 $= \texttt{left} + \mathrm{reverse}(\texttt{right})$，游標 $= \lvert\texttt{left}\rvert$。**`right` 必須逆序存**，否則游標右移退化成 $O(n)$。
- 四個操作全是棧頂操作；`min(k, 可移動量)` 的夾取**既防越界也是複雜度上界的依據**。
- 複雜度是 $O(\sum k_i)$，**不是每次 $O(1)$**；靠題目對 $\sum k$ 的約束才成立。
- 前提是**所有操作都在游標附近**；隨機位置操作要換平衡樹或塊狀鏈表。
- 對頂堆：`lo` 大根堆裝小的一半、`hi` 小根堆裝大的一半；不變量 $\max(\texttt{lo}) \le \min(\texttt{hi})$ 與大小差 $\in\{0,1\}$。
- 插入的三行無分支寫法（**先丟 `lo`、把 `lo` 的最大值移給 `hi`、再視情況搬回**）正確性見定理 3，別自己改順序。
- 中位數：奇數 `lo.top()`，偶數 `(lo.top() + hi.top()) / 2.0`（**注意 `int` 相加溢位**）。
- 要刪除任意元素（480）就配懶刪除（6.6）。
- **位置分界用堆疊（$O(1)$），大小分界用堆（$O(\log n)$）。**
