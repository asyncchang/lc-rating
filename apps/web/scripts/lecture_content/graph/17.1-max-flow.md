## 這個技術解決什麼問題

在有容量上限的網路中，求從源點到匯點能同時輸送的最大流量。它的真正威力在於建模：二分圖最大匹配、最小點覆蓋、有上下界的分配問題、某些「選或不選且互相衝突」的最優化，都能轉成最大流或最小割。

## 辨識題型的訊號

資源從一端分配到另一端且每條通道有容量；二分圖匹配（配對工作與工人）；「最少刪除多少條連結才能切斷兩端」（最小割）；「選了 A 就不能選 B 且要最大化收益」（最大權閉合子圖）。

## 核心想法與直覺

反覆在殘量網路上找一條從源點到匯點、每條邊都還有剩餘容量的路徑（增廣路），沿路推送可行的最大流量。關鍵設計是反向邊：推送 `f` 單位時，正向邊容量減 `f`、反向邊容量加 `f`，這讓後續的增廣可以「反悔」先前的決定，避免貪心走進死路。

Dinic 演算法在此基礎上加兩層優化：先用 BFS 按層次分層，再用 DFS 只沿「層次恰好加一」的邊多路增廣。

## 狀態／資料結構定義

用鏈式前向星存邊，邊成對存放（`i` 與 `i ^ 1` 互為反向），`cap[i]` 為剩餘容量。`level[x]` 為 BFS 分層結果；`iter[x]` 是當前弧優化的游標，記錄 `x` 的哪些出邊已經確定榨乾。

## 不變量或正確性證明

不變量一（流量守恆與容量限制）：每次沿增廣路推送 `f`（`f` 為路徑上剩餘容量的最小值）後，每條邊的流量仍不超過容量，且除源匯外每點流入等於流出。反向邊的加減恰好維持了這一點。

不變量二（分層單調）：Dinic 每個階段的最短增廣路長度嚴格遞增。因為一個階段內會把所有長度等於當前層數的增廣路榨乾，下一階段的最短路必然更長；路徑長度上限為 `n`，故階段數不超過 `n`。

終止即最優：當殘量網路中源點無法到達匯點時，令 `S` 為源點可達的節點集合。所有由 `S` 指向其補集的邊都必然滿載（否則可繼續到達），所有反向邊都必然為空。因此當前流量等於割 `(S, V \ S)` 的容量。由於任意流不超過任意割（最大流最小割定理的弱對偶方向），此流即為最大流，該割即為最小割。

## 逐步演算法

建圖並為每條邊同時加入容量為 0 的反向邊；BFS 從源點分層，若匯點不可達則結束；重置當前弧游標，DFS 沿層次遞增的邊多路增廣並累加流量；重複分層與增廣。

## C++17 模板

```cpp
struct Dinic {
  struct Edge { int to, next; long long cap; };
  vector<Edge> edges;
  vector<int> head, level, iter;
  int n;

  explicit Dinic(int n) : head(n, -1), level(n), iter(n), n(n) {}

  void addEdge(int from, int to, long long cap) {
    edges.push_back({to, head[from], cap});
    head[from] = edges.size() - 1;
    edges.push_back({from, head[to], 0});   // 反向邊，初始容量 0
    head[to] = edges.size() - 1;
  }

  bool bfs(int s, int t) {
    fill(level.begin(), level.end(), -1);
    queue<int> q;
    level[s] = 0;
    q.push(s);
    while (!q.empty()) {
      const int x = q.front();
      q.pop();
      for (int i = head[x]; i != -1; i = edges[i].next) {
        if (edges[i].cap > 0 && level[edges[i].to] == -1) {
          level[edges[i].to] = level[x] + 1;
          q.push(edges[i].to);
        }
      }
    }
    return level[t] != -1;
  }

  long long dfs(int x, int t, long long limit) {
    if (x == t) { return limit; }
    long long pushed = 0;
    for (int& i = iter[x]; i != -1; i = edges[i].next) {   // 當前弧優化
      const int y = edges[i].to;
      if (edges[i].cap > 0 && level[y] == level[x] + 1) {
        const long long got = dfs(y, t, min(limit - pushed, edges[i].cap));
        if (got > 0) {
          edges[i].cap -= got;
          edges[i ^ 1].cap += got;    // 反悔的本錢
          pushed += got;
          if (pushed == limit) { break; }
        }
      }
    }
    return pushed;
  }

  long long maxflow(int s, int t) {
    long long total = 0;
    while (bfs(s, t)) {
      copy(head.begin(), head.end(), iter.begin());
      total += dfs(s, t, LLONG_MAX);
    }
    return total;
  }
};
```

二分圖最大匹配的建法：源點連左部每點容量 1，右部每點連匯點容量 1，原有配對關係連容量 1，最大流即最大匹配數。

## 時間與空間複雜度

Dinic 一般圖為 $O(n^2 m)$，單位容量圖（如二分圖匹配）為 $O(m \sqrt{n})$，實務上遠快於理論上界。空間 $O(n + m)$。

## 常見錯誤與邊界條件

忘記加反向邊或反向邊初始容量設錯；邊陣列的起始索引不是 0，導致 `i ^ 1` 找錯配對邊；漏掉當前弧優化使複雜度退化；容量總和溢位需用 `long long`；無向邊應建成兩條容量皆為 `c` 的有向邊（而非一條）；源點與匯點編號與其他節點衝突。

## 與相似技巧的比較

匈牙利演算法程式更短，適合純二分圖匹配，但無法處理帶容量的一般網路；最小割問題一律轉成最大流；若邊還帶單位成本並要求最小總成本，則需最小費用最大流（把 BFS 換成 SPFA 找最短費用路）。

## 本節重點速查

反向邊提供反悔能力；Dinic 先分層再多路增廣；當前弧不可省；最大流等於最小割。
