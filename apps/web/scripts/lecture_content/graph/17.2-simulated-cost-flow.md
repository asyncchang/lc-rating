## 這個技術解決什麼問題

有些題目本質是最小費用最大流，但點數或邊數大到無法真的建圖。模擬費用流用一個堆直接「模擬」增廣的過程：貪心地做出當下最好的選擇，並保留一個可以反悔的憑證，等價於在殘量網路上走反向邊。它常以「反悔貪心」的名字出現。

## 辨識題型的訊號

依序處理一串物品或事件，每步做出取捨並累積收益；容量或次數有限制；純貪心會在後面才顯現出錯誤，需要「早知道就不那樣選」。例如「最多做 `k` 個任務使收益最大」「賣出股票且可反悔」。

## 核心想法與直覺

費用流的反向邊代表「撤銷先前決定」。在只有單一資源約束的結構上，我們不必顯式建圖：先照貪心選，同時把「撤銷這次選擇的代價」丟進堆裡；當後面出現更好的機會時，從堆中取出最便宜的撤銷憑證，一併結算。這一取一放，恰好對應一次沿反向邊的增廣。

以「買賣股票可反悔」為例：在價格 `p` 賣出時，同時把 `p` 放回堆中，代表「這筆交易可以被改成在 `p` 買入」，於是後續更高價可以接上，等價於把兩段交易併成一段更長的。

## 狀態／資料結構定義

一個優先佇列存放可反悔的憑證：內容通常是「先前選擇的代價」或「撤銷後可回收的收益」。另有累計答案與已用資源計數。

## 不變量或正確性證明

不變量：處理完前 `i` 個元素後，答案是「只考慮前 `i` 個元素」的最優解，且堆中恰好保存所有可用的反悔機會。

正確性來自費用流的最優性條件：一個流是最小費用的，當且僅當殘量網路中不存在負費用環。模擬過程每一步都選擇當前最優的增廣（貪心取最便宜的憑證），相當於逐次增廣且每次都走最短費用路；由最小費用流的理論，「每次沿最短費用路增廣」得到的每個中間流都是該流量下的最優解。因此逐元素處理時維持的最優性可以歸納傳遞到最後。

要讓這個對應成立，問題結構必須滿足交換律式的可分解性——資源是單一維度且憑證之間可自由替換。若約束有多維（例如同時限制數量與重量），模擬費用流通常失效，必須回到真正的費用流或 DP。

## 逐步演算法

依序掃描元素；若資源尚有餘裕就直接採用，並把反悔憑證入堆；若資源已滿，比較「當前元素」與「堆頂最差的既有選擇」，更優就替換並更新答案，同時把新的憑證入堆；掃描結束即得答案。

## C++17 模板

以「最多選 `k` 個任務使收益最大，且可反悔」為經典骨架：

```cpp
// items 依某個順序給出，value 為收益；最多選 k 個，求最大總收益。
long long maxProfit(const vector<int>& value, int k) {
  priority_queue<int, vector<int>, greater<int>> heap;  // 小根堆存已選收益
  long long total = 0;

  for (int v : value) {
    if (static_cast<int>(heap.size()) < k) {
      heap.push(v);
      total += v;
    } else if (!heap.empty() && v > heap.top()) {
      total += v - heap.top();    // 反悔：撤掉最差的一次選擇
      heap.pop();
      heap.push(v);
    }
  }
  return total;
}
```

「可反悔的買賣股票」則把賣出價再放回堆中，讓後續交易得以接續：

```cpp
long long maxProfitUnlimitedRegret(const vector<int>& prices) {
  priority_queue<int, vector<int>, greater<int>> heap;
  long long total = 0;
  for (int p : prices) {
    if (!heap.empty() && p > heap.top()) {
      total += p - heap.top();
      heap.pop();
      heap.push(p);      // 憑證：這筆賣出可改寫成買入
    }
    heap.push(p);
  }
  return total;
}
```

## 時間與空間複雜度

每個元素至多入堆常數次，時間 $O(n \log n)$，空間 $O(n)$。相較之下真正的最小費用最大流通常是 $O(f \cdot nm)$ 級別，這正是模擬的價值所在。

## 常見錯誤與邊界條件

憑證的定義沒想清楚，導致反悔後的答案重複計算或漏算；用大根堆與小根堆搞混；資源未滿時忘了直接採用；把多維約束的題目硬套本法；答案累加溢位需用 `long long`；反悔的差值可能為負，必須先比較再替換。

## 與相似技巧的比較

一般貪心不保留反悔機會，只在「無後效性」極強的題目才正確；DP 一定正確但狀態數可能爆炸；真正的費用流最通用但太慢。模擬費用流位於三者之間：保有費用流的最優性，卻只花貪心的成本，代價是需要為每個題型單獨設計憑證。

## 本節重點速查

堆裡放的是反悔憑證；一次替換等於一次反向邊增廣；單一資源維度才適用；先比較再替換。
