## 這個技術解決什麼問題

樹是遞迴定義的結構：一個節點加上左右兩棵子樹。要對每個節點做一次處理，最自然的方式就是讓程式碼的形狀跟著資料的形狀走——**遞迴到左子樹、處理自己、遞迴到右子樹**。這就是遍歷。

它本身不是「技巧」而是**基礎設施**：後面所有樹題（DFS 求值、樹形 DP、LCA、建樹）都是在遍歷的骨架上塞進不同的處理內容。搞清楚前序、中序、後序三者的差別，等於掌握了「在什麼時機點你手上有什麼資訊」。

## 狀態／資料結構定義

- `TreeNode { int val; TreeNode *left, *right; }`，空子樹用 `nullptr` 表示。
- 遞迴函式 `dfs(node)`：語意是「處理以 `node` 為根的整棵子樹」。出口固定是 `if (!node) return;`。
- 三種順序的差別只在**處理自己這一行放在哪裡**：
  - 前序（144）：處理自己 → 左 → 右。進入節點時處理。
  - 中序（94）：左 → 處理自己 → 右。左子樹做完時處理。
  - 後序（145）：左 → 右 → 處理自己。兩棵子樹都做完時處理。
- 迭代版需要顯式堆疊，因為要手動保存「回來之後該做什麼」。

## 不變量或正確性證明

**每個節點恰被訪問一次。** 用結構歸納證明 `dfs(node)` 恰好訪問以 `node` 為根的子樹中的每個節點各一次。基底：`node == nullptr` 時訪問 0 個節點，成立。歸納：`dfs(node)` 訪問 `node` 自己一次，並呼叫 `dfs(node->left)` 與 `dfs(node->right)`；由歸納假設，兩者分別恰訪左右子樹各節點一次。由於樹的結構保證**左子樹、右子樹、根三者的節點集合兩兩不交且並集為整棵子樹**，故總計恰為每個節點一次。

這裡點名兩個前提。其一，輸入必須真的是樹——無環且每個節點只有一個父節點。若有環（例如題目給的是圖），遞迴不會終止；若某節點有兩個父節點（DAG），它會被訪問多次，上面的「不交」條件失效。其二，遞迴深度等於樹高，斜樹會退化成 $O(n)$ 深。

**中序遍歷與 BST 的關係。** 若樹是二元搜尋樹，中序遍歷輸出遞增序列。證明同樣用結構歸納：由 BST 性質，左子樹所有值 < 根 < 右子樹所有值；由歸納假設，左子樹中序輸出遞增、右子樹中序輸出遞增；中序把三者依「左、根、右」串接，故整體遞增。這條性質是 98、230、99、二元搜尋樹一整節（2.9）的基礎，值得單獨記住。

**前序與後序的資訊時機。** 進入節點時，你手上有的是「從根到此節點這條路徑」的資訊（自上而下累積），所以前序適合傳遞路徑和、深度、路徑上的最大值（2.2）。離開節點時，你手上有的是「兩棵子樹回傳的彙總」，所以後序適合求高度、子樹和、子樹節點數（2.3）。**選錯時機，需要的資訊根本還不存在**——這是所有樹 DFS 題最核心的判斷。

**迭代中序的不變量。** 堆疊中自底向上存的是「當前節點的祖先鏈中，右子樹尚未處理的那些節點」。每次先把左鏈全部壓入，彈出時該節點的左子樹必然已處理完畢，故此時輸出它是正確的中序位置。

## 時間與空間複雜度

三種遍歷都是 $O(n)$ 時間——每個節點常數次操作，由上面的歸納論證直接得出。

空間 $O(h)$，$h$ 為樹高：遞迴版是呼叫堆疊，迭代版是顯式堆疊（存的正是祖先鏈）。平衡樹 $h = O(\log n)$，斜樹 $h = n$，故最壞 $O(n)$。若輸出要收集所有節點值則另計 $O(n)$。

Morris 遍歷可做到 $O(1)$ 空間，代價是暫時修改樹結構（利用葉節點的空右指標當回程線索），$O(n)$ 時間不變。

## 與相似技巧的比較

- BFS（2.13）逐層訪問，空間是 $O(w)$（最大層寬）而非 $O(h)$；求「最短層數」「層平均」時用 BFS，求「路徑」「子樹彙總」時用 DFS。
- 前序遍歷的訪問順序與 BFS 都能重建結構嗎？不行——單靠前序無法唯一確定樹，需要搭配中序（見 2.10），或改用含空節點標記的序列化（297）。
- 一般樹（3.1）的遍歷沒有「中序」的概念（子節點不只兩個），只剩「進入時處理」與「離開時處理」兩種時機。

## 本節重點速查

出口 `if (!node) return;`，然後左、右兩次遞迴；三種順序只差「處理自己」放哪一行。**前序手上有根到此的路徑資訊，後序手上有子樹的彙總資訊**，選錯時機資訊就不存在。中序走 BST 得遞增序列。時間 $O(n)$、空間 $O(h)$。
